# Telemetry and Privacy

Recce OSS sends anonymous usage data and error reports so the team can see which features data teams use and fix problems faster. This page explains what is sent, what is not, and how to turn it off.

This page describes Recce 1.74.0 and later. It covers Recce you run yourself: the `recce` CLI, `recce server`, the MCP server, and the `recce-cloud` CLI. Recce Cloud instances run on Recce's infrastructure and are not controlled by these settings.

## Turn telemetry off

You have two options. Either one turns off **every** telemetry path: usage analytics, error reporting, and the trackers in the Recce web UI.

### Option A: Edit your profile

Recce stores its settings in `~/.recce/profile.yml`, created the first time you run Recce. Set `anonymous_tracking` to `false`:

```yaml
# ~/.recce/profile.yml
user_id: 3f1c...        # random id, generated by Recce
anonymous_tracking: false
```

Telemetry is on only when `anonymous_tracking` is exactly `true`. Any other value, including `no` or `off`, or a missing key, turns it off.

### Option B: Set an environment variable

Set either variable to `1`, `true`, `yes`, or `on`:

```shell
export RECCE_DISABLE_TELEMETRY=1
# or the cross-tool convention
export DO_NOT_TRACK=1
```

The environment variable overrides the profile, so it is the simplest choice for CI runners, containers, and shared machines where you don't control `~/.recce`.

!!! info "When the change takes effect"

    Each CLI command reads the setting when it starts. For a `recce server` or MCP server that is already running, restart it, then reload any open Recce web UI tab.

When telemetry is off, Recce does not start error reporting, sends no usage events, removes its tracking cookie, and drops any usage events that were queued but not yet sent.

## What is sent when telemetry is on

### Usage events

Recce sends anonymous usage events to Amplitude and PostHog. Each event is tied to a random `user_id` from your profile, not to your name, email, or account.

| Event | What it includes |
|-------|------------------|
| Command run | Command name, success or failure, duration, Recce, dbt, and Python versions, adapter and warehouse type (for example `duckdb` or `snowflake`), operating system |
| Web UI and API activity | Which feature or endpoint was used and the check type, for example `query_diff` |
| Environment | Whether Recce runs in CI, GitHub Codespaces, or a Recce Cloud instance, and the CI runner type |

Repository names, branch names, and artifact paths are sent only as one-way SHA-256 hashes, so they cannot be read back.

### Web UI analytics

When you open the Recce web UI from `recce server`, the browser loads:

- **Amplitude and PostHog**, which record page views and clicks, including the text of the element you clicked. Amplitude also records **anonymized session replays** of the Recce UI. The parts of the UI that show model names, SQL, and query results are masked, so replays do not contain them.
- **Google Tag Manager**.

None of these load when telemetry is off.

### Error reports

When Recce hits an unexpected error, it sends a report to Sentry with the error type, the stack trace, the Recce version, your operating system and time zone, and your anonymous `user_id`. Recce also sends performance traces for its own operations.

Before a report leaves your machine, Recce removes:

- your machine's hostname
- command-line arguments, which can contain tokens or passwords
- home-directory paths (rewritten to `~`)
- error messages from dbt, your warehouse, and failed checks, because they can contain SQL and table or column names (the error type and stack trace are kept)
- log output, local variables, request bodies, headers, cookies, and query parameters

## What usage events and error reports never contain

- Query results, row values, or profiling statistics
- Warehouse credentials, dbt profiles, or API tokens
- SQL, model code, or the content of your checks

Session replays are anonymized and don't contain these either. The one place on-screen text can appear is a web UI click event, which records the text of the element you clicked: usually a button label, but a model name if you click a node in the lineage view. If that is a concern, turn telemetry off.

!!! warning "Recce 1.73 and earlier"

    Before Recce 1.74.0, `anonymous_tracking: false` turned off usage events but not error reporting or the web UI trackers, and `RECCE_DISABLE_TELEMETRY` covered PostHog only. Upgrade to get the full opt-out:

    ```shell
    pip install -U recce
    ```
